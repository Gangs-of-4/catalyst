Idea: $ARGUMENTS

Check it against `context/mvp.md` and `context/feature-backlog.md`. Reply in at most 8 lines:

1. **Fit:** In the MVP (name the capability C1–C12) / an existing backlog item (number and phase) / new.
2. **Why:** one line.
3. **Touches:** modules and whether it changes `context/contracts.md`.
4. **Conflicts:** any Accepted ADR, Proposed ADR or open decision (D1–D7) it depends on or would reverse.
5. **Suggestion:** build now, or add it to the backlog. If it's new, propose the one-line backlog entry with the next free number (101+) and a phase.

This is advisory only. Never tell the member they can't work on it. If they want to add it to the backlog, make the edit when asked.
